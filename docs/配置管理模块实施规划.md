# 配置管理模块实施规划

> 对应 `docs/TODO.md` §二（2.1 / 2.2 / 2.3）。
> 最近更新：2026-07-19
> 风格与深度对齐 `docs/CUSTOM-RULES-PARALLEL-PLAN.md`。

---

## 一、背景与目标

把当前散落在 `GameSetup.vue`（规则编辑）和 `PlantManager/`（植物库）的配置能力，整合为统一的「配置管理模块」，且两类配置都采用「多套预设 + 当前选中一套」模式。开房间入口（`GameSetup.vue`）的流程配置项**保留**，但改为**读取配置模块中选中的预设**（不再就地独立编辑）。

三个子目标：

- **2.1** 新增统一配置管理模块入口（规则预设 + 植物包预设并列）。
- **2.2** 规则配置升级为「多套预设 + 选中」（**主要新工作**）。
- **2.3** 植物包预设整合进统一模块（**预设层已实现**，需迁移/归口）。

## 二、关键现状（已核对）

### 2.1 规则配置 — 单套、直接编辑、**无预设**
- 默认值：`src/config/defaultRules.js` 聚合 `src/config/rules/{sideNames,sideSelection,bpSequence,limits}.js`。
- 存储：`gameStore.state.ruleConfig`（单一对象，直接编辑）。
- 序列化（**已整体处理 `ruleConfig`**）：`getSyncPayload`（`gameStore.js:557`、`:712`）、`loadFromLocalStorage`（`:578` 深合并默认值）、`applySyncState`（`:697` 深合并）。
- 编辑器：`src/components/RulesEditor/{BPRulesEditor,SideRulesEditor}.vue`，直接 `v-model` 到 `store.ruleConfig.*`。
- 相关 getter：`sideName(road)`（`:81`）、`maxPlantUsage`（`:135`）、`currentBPTemplate`（`:136`）。

### 2.2 植物包预设 — **多套 + 选中（已实现）**
- 数据层 `src/data/plantConfigs.js`：localStorage key `bpPlantConfigs`，结构 `{ configs:[], activeConfigId }`。
- 预设结构：
  ```js
  { id, name, description, createdAt, updatedAt,
    plants: [{ id, name, description, type, image(base64), builtin }],
    hiddenBuiltinPlants: [] }
  ```
- API：`getAllConfigs / getActiveConfig / getConfigById / saveConfig / loadConfig / deleteConfig / renameConfig / setActiveConfig / exportConfig / importConfig`。
- 机制：预设存 localStorage（图片转 base64）；`loadConfig` 时**清空 IndexedDB 重写** + `setActiveConfig` + `window.location.reload()`。
- UI `src/components/PlantManager/ConfigManager.vue`：卡片网格 + 当前选中徽标 + 保存/加载/重命名/导出/导入/删除。
- 植物库本体 `src/data/customPlants.js`：IndexedDB `BP_PlantManager` v1，单 store `customPlants`（keyPath=id），全局缓存 `customPlantsCache`，`getAllPlantsSync()`。

### 2.3 多人同步 — **已天然满足「只下发选中包」**
- `customPlants` 消息：host 广播的是**加载后的** `{ plants, hiddenBuiltinPlants }`；选手端 `connectionStore.handleCustomPlantsSync`（`:213`）清空 IndexedDB 重写 + `updateCache`。
- `ruleConfig` 随 `stateUpdate` / `getSyncPayload` 整体同步。
- **结论：协议层（`docs/network-protocol.md`）无需改动**。"只下发选中包"由现有 host 广播逻辑天然达成。

### 2.4 路由
- `src/router/index.js`：`/`(setup) → `/ban-pick` → `/result` → `/victory` + dev `/dev/sim`。
- 守卫按 `gameStatus` 跳转；**无独立配置管理路由**。

## 三、核心设计决策（已确定）

**预设粒度：两类预设各自独立**（方案 A，已采纳）。

| | 方案 A（已采纳）：两类独立 | 方案 B（未采纳）：组合预设 |
|---|---|---|
| 结构 | 规则预设列表 + 植物包预设列表，各有「当前选中」 | 一个赛事预设 = ruleConfig + plants + hiddenBuiltinPlants |
| 复用 | 直接复用现有 `plantConfigs.js`，新增同构 `ruleConfigs.js` | 需改造现有 plantConfigs 结构 |
| 组合性 | 同一植物包可配不同规则（灵活） | 规则与植物强耦合，组合数膨胀 |
| 切换 | 两个独立「当前选中」 | 一键切完整赛事配置 |

**已采纳方案 A**（与现有实现一致、改动最小、符合 TODO 把 2.2/2.3 分列的意图）。规则预设与植物包预设各自独立选预设、自由组合；方案 B（组合预设）未采纳。

## 四、数据契约：预设存储

### 4.1 植物包预设（现状，不变）
localStorage `bpPlantConfigs` = `{ configs:[PlantConfig], activeConfigId }`（见 §2.2）。

### 4.2 规则预设（**新增，与植物包同构**）
localStorage `bpRuleConfigs` = `{ configs:[RuleConfig], activeConfigId }`

```js
RuleConfig = {
  id: 'ruleconfig_<timestamp>',
  name: '标准赛',
  description: '',
  createdAt, updatedAt,
  ruleConfig: { ...defaultRules }   // 整体存一份 ruleConfig 快照
}
```

- `activeConfigId` 决定开房间时载入哪套规则到 `gameStore.ruleConfig`。
- 沿用「整体存取 + 深合并默认值」约定（向后兼容旧存档与新增配置字段）。
- 规则无图片，**不涉及 IndexedDB**，比植物包实现更简单。

### 4.3 选中态如何作用于 gameStore
- 进入 setup / 应用启动：若存在激活规则预设，`gameStore.ruleConfig = { ...defaultRules, ...activeRuleConfig.ruleConfig }`。
- 植物包：现有 `loadConfig` 已实现（清空 IDB 重写）。

## 五、实施阶段

### Phase 1 — 规则预设数据层（`src/data/ruleConfigs.js`，新增）
- 仿 `plantConfigs.js` 导出同名 API：`getAllConfigs / getActiveConfig / saveConfig / loadConfig / deleteConfig / renameConfig / setActiveConfig / exportConfig / importConfig`。
- `saveConfig(name, desc)`：快照当前 `gameStore.ruleConfig` 存为新预设。
- `loadConfig(id)`：写回 `gameStore.ruleConfig`（深合并默认值）+ `setActiveConfig`；**无需刷新页面**（规则是内存对象，直接赋值即生效，区别于植物包的 IndexedDB 重写）。

### Phase 2 — 统一配置管理模块入口
- 新增 `src/components/ConfigManager/index.vue`：Tab 分两栏「规则预设」「植物包预设」。
- 抽出通用 `src/components/ConfigManager/PresetList.vue`（基于现有 `PlantManager/ConfigManager.vue` 的卡片网格 + CRUD UI，用 props 注入数据源 API）；两个 Tab 各自传 `ruleConfigs` / `plantConfigs` 的 API。
- 「植物包预设」栏承载现有 `plantConfigs` 逻辑（从 `PlantManager/ConfigManager.vue` 迁入，原文件可移除或改为薄包装）。

### Phase 3 — 开房间入口改为「读取选中」
- `GameSetup.vue` 的 `SideRulesEditor` / `BPRulesEditor` 区块：
  - 默认**只读展示**「当前选中规则预设」的规则值。
  - 提供「切换预设」入口（下拉选预设，或跳配置管理模块）。
  - 不再就地编辑 `ruleConfig`；修改规则内容须去配置管理模块（开房间处只读 + 切换预设下拉 +「去配置管理修改」入口）。
- 植物包：setup 页显示「当前选中植物包：xxx」，入口跳配置管理。

### Phase 4 — 路由 + 入口按钮
- `src/router/index.js` 新增路由 `/config`，组件 = 配置管理模块。
- 守卫放行：`beforeEach` 中 `if (to.name === 'config') return true`，避免被 `gameStatus` 守卫拦截（任意时刻可配置）。
- `GameSetup.vue` 顶部加「⚙ 配置管理」按钮 → `/config`。

### Phase 5 — 文档同步
- 更新 `docs/TODO.md` §二（2.3 现状已修正为「预设层已实现」）。
- 更新 `CLAUDE.md`：记录「配置管理模块」职责 + `ruleConfigs` / `plantConfigs` 双预设契约 + 开房间入口「读取选中」约定。

## 七、多人同步（无需改协议）

- **植物**：host 已广播选中包加载后的 `{ plants, hiddenBuiltinPlants }`，选手端照单全收 → 「只下发选中包」已满足。
- **规则**：`ruleConfig` 随 `stateUpdate` 整体同步；host 切换激活规则预设后，由 `loadActiveRuleConfig` 写入 `gameStore.ruleConfig`，下一帧 `syncState` 即把新规则广播给全员。
- **触发点**：切换预设后，host 需主动触发一次状态同步（规则走 `syncState`；植物走既有 `customPlants` 广播）。

## 九、已确定的设计决策

1. **预设粒度 = 方案 A（两类独立）**：规则预设与植物包预设各自独立列表 + 各自「当前选中」，开房间自由组合。
2. **开房间规则区 = 只读 + 可切换预设**：只读展示选中规则预设的值 + 切换预设下拉；修改规则内容去配置管理模块，开房间不就地编辑。
